GUIDE DE CONFIGURATION — CV PUBLIC (FRANÇAIS)
================================================

Le code du site est prêt à se connecter à Supabase, mais aucun stockage distant ne peut fonctionner avant cette configuration. Ne publiez pas le site en pensant que le stockage est déjà actif.

1) Créer un projet Supabase
- Ouvrez https://supabase.com/ et créez un projet.
- Dans Project Settings / API, copiez Project URL et la clé anon/publishable.
- Dans index.html, remplacez YOUR_SUPABASE_PROJECT_URL et YOUR_SUPABASE_ANON_OR_PUBLISHABLE_KEY par ces valeurs.
- N'utilisez JAMAIS la clé service_role dans le code public du site.

2) Créer un bucket public pour les CV
- Dans Storage, créez un bucket nommé exactement : public-cvs
- Activez l'option Public bucket. Cela rend les fichiers consultables par toute personne qui a leur URL.
- Limitez la taille maximale du fichier à 5 MB et, si l'interface le permet, autorisez seulement PDF, DOC et DOCX.

3) Créer la table et les autorisations
Dans Supabase → SQL Editor, exécutez :

create table if not exists public.public_cvs (
  id bigint generated by default as identity primary key,
  full_name text not null check (char_length(full_name) between 1 and 100),
  specialty text not null check (char_length(specialty) <= 100),
  diploma text not null check (char_length(diploma) between 1 and 160),
  file_path text not null unique,
  file_url text not null,
  created_at timestamptz not null default now()
);

alter table public.public_cvs enable row level security;

create policy "Public can view published CV metadata"
on public.public_cvs for select to anon, authenticated using (true);

create policy "Public can submit CV metadata"
on public.public_cvs for insert to anon, authenticated with check (
  char_length(full_name) between 1 and 100
  and char_length(specialty) between 1 and 100
  and char_length(diploma) between 1 and 160
);

-- Storage: allow anonymous visitors to upload and remove their own failed upload is not possible to enforce by identity without accounts.
create policy "Public can upload CV files"
on storage.objects for insert to anon, authenticated
with check (bucket_id = 'public-cvs');

IMPORTANT: ces politiques autorisent les dépôts anonymes et la lecture publique. Elles sont simples pour un prototype, mais elles ne fournissent ni modération, ni limitation fiable contre le spam, ni gestion d'identité. Pour un site public de production, ajoutez une validation côté serveur, CAPTCHA/rate limiting et un processus de modération avant publication.

4) Publier sur GitHub Pages
- Enregistrez index.html avec les deux valeurs Supabase.
- Gardez le dossier images/ au même niveau que index.html.
- Envoyez les fichiers modifiés vers votre dépôt GitHub, puis attendez la mise à jour de GitHub Pages.
- Testez avec un CV non sensible avant d'annoncer le service.

5) Fonctionnement et confidentialité
- Les visiteurs peuvent déposer un CV, et tous les visiteurs peuvent consulter/télécharger les CV publiés.
- Le formulaire demande un consentement explicite à la publication.
- Les CV peuvent contenir des données personnelles. Informez les diplômés, obtenez leur autorisation et demandez-leur de ne pas publier des données sensibles qu'ils ne souhaitent pas rendre publiques.
- Cette première version n'a pas de bouton de suppression/édition, ni de modération administrative. Les suppressions devront être effectuées via Supabase Storage et la table public_cvs.
- Le formulaire d'inscription général utilise encore FormSubmit avec YOUR_EMAIL@example.com : remplacez cette valeur par l'adresse destinataire si vous voulez recevoir les inscriptions par e-mail.

Si vous ne voulez pas que les CV soient accessibles à tous, ne créez pas un bucket public et ne déployez pas cette version telle quelle.
